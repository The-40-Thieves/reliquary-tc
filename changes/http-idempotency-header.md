- **`Idempotency-Key` header over HTTP.** A tool that accepts an idempotency key now also takes it from the `Idempotency-Key` request header when the arguments carry none. A header that disagrees with the argument, is empty, is longer than 128 characters, or contains a comma (which is how a repeated header arrives) is refused with `validation_error` without echoing the key; a tool that accepts no key ignores it; a JSON-RPC batch ignores it. The hash stored with a claim no longer includes the key, so the header and argument forms of one call match each other. Claims written by an older version still replay. An older version refuses a claim written by this one with `idempotency_key_mismatch` until the claim expires, so after a rollback retry with a new key rather than expecting a replay.
